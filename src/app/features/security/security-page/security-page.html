Modo demonstrativo

Este é um projeto de portfólio. Use apenas dados fictícios: a API de desenvolvimento (JSON Server) não tem autenticação, autorização nem proteção de servidor, e qualquer pessoa com acesso a ela pode ler os dados.

Como a demonstração trata seus dados

  • Senha: nunca é guardada. Fica só um hash PBKDF2-SHA256 com 600.000 iterações e salt aleatório, verificado em tempo constante.
  • Sessão: nome, e-mail e id ficam no sessionStorage criptografados com AES-256-GCM. A chave não é exportável, fica no IndexedDB e é descartada ao sair.
  • Preferências: tema e densidade ficam no localStorage, sem dados pessoais.
  • Limites: criptografia no navegador não protege contra XSS, extensões maliciosas ou um dispositivo comprometido: um script na página usa as mesmas chaves. Em um sistema real, autenticação, autorização e validação ficam no servidor, e senhas usam um algoritmo como Argon2id.

Laboratório de criptografia

Uma chave AES-256 é derivada da frase com PBKDF2-SHA256 e um salt aleatório. O texto é criptografado com AES-GCM e um IV (vetor de inicialização) aleatório de 96 bits, novo a cada operação, de modo que o mesmo texto gera resultados diferentes. O GCM também autentica os dados: qualquer alteração faz a descriptografia falhar. A frase e a chave não são guardadas; só o salt e o IV acompanham o resultado, pois não são secretos.

Limpar os dados fictícios

  • Neste navegador: sair apaga a sessão e a chave dela; limpar os dados do site no navegador remove também as preferências.
  • No ambiente de desenvolvimento: npm run db:reset restaura a API simulada ao estado inicial, apagando os dados de todos os usuários.
